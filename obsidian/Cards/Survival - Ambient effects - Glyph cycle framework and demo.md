Generic in-engine glyph-cycle abstraction, plus a standalone exploration binary that lets us A/B many candidate cycles for fire (and later other effects) before committing one to the main game.

## Two deliverables

1. **`GlyphCycle` effect type** in the main engine — first-class, hashable, deterministic. Lit fires (and any future cycling glyphs) consume it.
2. **`glyph_cycle_explorer` standalone binary** — tiles the SDL window with many candidate cycles drawn from a curated + wide CP437 pool. Same render path as the real game; same atlas; runs on desktop and Miyoo.

The framework gets drafted first because the explorer is implemented in terms of it.

## `GlyphCycle` abstraction

```rust
// src/effects/glyph_cycle.rs
pub struct GlyphCycle {
    pub glyphs: &'static [u8], // CP437 bytes, 2..8 entries
    pub cadence_frames: u32,   // frames per glyph step
    pub phase_seed: u32,       // per-instance offset so multiple cycles don't sync
}

impl GlyphCycle {
    pub fn glyph_at(&self, render_tick: u32) -> u8 {
        let step = ((render_tick / self.cadence_frames) + self.phase_seed as u32)
            as usize % self.glyphs.len();
        self.glyphs[step]
    }
}
```

Pure function of `(render_tick, phase_seed)` — fits the brainstorm's "static-y effects as pure functions" rule. No mutable state, no save impact, no allocation.

Consumers store a `GlyphCycle` (or an index into a static table of them). Lit fires get a default cycle plus a `phase_seed` derived from a stable per-fire id (hash of spawn `(wx, wy, world.seed)` is fine — fires don't move).

## Where it plugs in

- `src/effects/fire.rs` — replace the `*` literal at `main.rs:984` with `fire.cycle.glyph_at(render_tick)`.
- `render_tick: u32` added to `main.rs` main loop, threaded into the per-cell compose block.
- Per-fire `phase_seed` computed at fire spawn, stored on the `ItemMetadata::Lit` variant or a sidecar map keyed by fire id.

Dirty-cell cost: 1 cell per fire becomes dirty once per `cadence_frames`. At cadence 6 and 5 fires, ≈ 0.8 cells/frame avg. Trivial.

## Curated CP437 fire-y pool

Hand-picked starting set (will be refined by the explorer):

| Hex | Glyph | Note |
|---|---|---|
| 0x2A | `*` | current fire glyph |
| 0x18 | `↑` | upward arrow |
| 0x1E | `▲` | filled triangle |
| 0x06 | spade | curvy |
| 0xB0 | `░` | light shade |
| 0xB1 | `▒` | mid shade |
| 0xF8 | `°` | degree |
| 0xA7 | `§` | wavy |
| 0xB6 | `¶` | curly |
| 0xEC | `∞` | weird |
| 0x0F | `☼` | sun/bright |

Curated list lives in `effects/glyph_cycle.rs` as `pub const CURATED_FIRE_GLYPHS: &[u8] = &[...]`.

## Wide pool

All CP437 glyphs with vertical / pointy / wispy shapes. Generated by a hand-filtered include of indices from `assets/CP437_MAP.md`. Lives next to the curated pool: `pub const WIDE_FIRE_GLYPHS: &[u8] = &[...]`.

The explorer pulls random subsets of length 2..5 from `CURATED ∪ WIDE`.

## Standalone binary

`examples/glyph_cycle_explorer.rs` (Cargo handles `examples/` automatically — runs via `cargo run --release --example glyph_cycle_explorer`).

- Re-uses `src/render.rs::load_atlas` and `draw_glyph` directly (these are already pure helpers that take a surface). No engine forking.
- Layout: tile the 640×480 viewport with `N` "labs," each a 3-cell strip showing one glyph cycle plus a tiny numeric label (cycle index). 10×6 grid of labs at most, so ~60 cycles visible per page.
- Inputs: `→` next page (next random batch), `←` previous, `R` re-roll the current page's random subsets, `S` dump the currently focused cycle to stdout as a `GlyphCycle { glyphs: &[...], cadence_frames: X, phase_seed: 0 }` literal we can paste into `effects/fire.rs`.
- Cadence: each row uses a different cadence (4, 6, 8, 12 frames) so we can see how speed reads.
- Phase: each lab gets its own random `phase_seed` so identical-glyph rows don't synchronize.

Miyoo build: the binary is `cargo run --example` on desktop; for Miyoo we add an opt-in script that cross-builds it via the existing `cross/build-onion.sh` pipeline. Probably worth doing — flicker reads very differently on the LCD than on a desktop monitor.

## Cost

- Engine side: GlyphCycle is one branchless integer-divide and array index. Negligible.
- Explorer side: ~60 cycles × 1 dirty cell each on every cadence step. Worst case 60 dirty cells/frame. Within budget.

## Verification

- Desktop: `cargo run --release --example glyph_cycle_explorer` opens the grid. Mash R to verify random subsets actually shuffle.
- Miyoo: deploy, observe the LCD, pick a winner. Paste the resulting `GlyphCycle` literal into `effects/fire.rs`.
- Engine integration: `cargo run --release` with at least one lit fire, confirm the chosen cycle plays and that two fires near each other don't synchronize.
